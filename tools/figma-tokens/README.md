# Figma Tokens CLI

Generates Swift and Kotlin design token code from Figma variables.

## Key Principles

- **Zero hardcoded names** — collection roles (primitive, semantic, product, leaf) are inferred structurally from the data:
  - Single-mode → primitive
  - Multi-mode with identical branches → product group (largest = base, others = flavor)
  - ≥2 upstream deps → leaf
- **Identical structure** for Swift and Kotlin output
- **Fully dynamic** — if Figma structure changes, regeneration produces compilable code without config changes
- **Explicit exclusions** — design-only Figma collections are skipped via the source-controlled [`configs/collections.toml`](configs/collections.toml)

## Excluding collections and branches

Some Figma collections exist only for design work (e.g. `figma-only`) and must never
reach generated code. They are listed in the git-tracked
[`configs/collections.toml`](configs/collections.toml):

```toml
exclude = [
    "figma-only",
    "wip-*",     # shell-style globs are supported
]

exclude-branches = [
    "base/apple",   # drop the `apple` group from the `base` collection only
    "apple-color",  # bare name == `*/apple-color` (every collection)
]
```

- Matching is case-insensitive and supports `*`, `?`, `[seq]` globs.
- The file is loaded automatically; override it with `--collections-config <path>` or
  the `collections-config` key in the main config.
- Excluded collections are dropped before resolution, and any alias pointing into them
  is replaced by the already-resolved literal value, so generated code never references
  a class that was not produced.
- `exclude-branches` works one level deeper: a **branch** is the first segment of a Figma
  variable name (`apple` in `apple/system-black`), which becomes a sub-package/data class
  inside a collection. Its tokens, data class and factory parameters are removed, and
  `branches` / `ext_deps` / builder wiring are recomputed so factories and builders stay
  in sync. Aliases into a dropped branch fall back to their literal value.
- A pattern that matches no collection and no branch is reported with a `[WARN]`, so a
  typo (e.g. `apple` when the collection is really named `apple-color`) is never a silent
  no-op.
- Exclusions are re-applied when generating with `--from-intermediate`, so a stale
  `tokens.json` still honours the current config.

## Requirements

- Python 3.9+
- `pip install click requests tomli`

## Quick Start

```bash
cd tools/figma-tokens

# Install deps
pip3 install click requests tomli

# Run with config (fetches from Figma API, saves JSON to tools/figma-tokens/json/)
PYTHONPATH=src python3 -m figma_tokens.cli --config configs/android.toml

# Or with env var for token
FIGMA_TOKEN=figd_xxx PYTHONPATH=src python3 -m figma_tokens.cli --config configs/android.toml

# Dry run (see what would be generated)
PYTHONPATH=src python3 -m figma_tokens.cli --config configs/android.toml --dry-run

# Generate from saved intermediate JSON (no Figma fetch needed)
PYTHONPATH=src python3 -m figma_tokens.cli --from-intermediate json/tokens.json \
  --language kotlin --output output/ --package com.example.tokens
```

### Output Structure

```
tools/figma-tokens/
├── json/                 # Always here (json-output override is resolved against this tool dir)
│   ├── figma-raw.json    # Raw Figma API response (for debugging)
│   └── tokens.json       # Intermediate JSON (platform-independent resolved tokens + graph)
output/
└── com/example/tokens/   # Generated Kotlin code
    ├── base/
    ├── components/
    └── ...
```

### Generated file conventions

- Every generated `.kt` / `.swift` file starts with a banner: *"This file is generated by the figma-tokens tool. DO NOT MODIFY — any manual changes will be overwritten the next time tokens are regenerated from Figma."*
- Figma variable `description`s are carried through the pipeline (and the intermediate JSON) and emitted as documentation: KDoc `@property` entries on the owning data class for Kotlin, `///` DocC comments on the property for Swift.

`figma-raw.json` and the intermediate `tokens.json` always land in `tools/figma-tokens/json/`, never next to the generated source `output` (so they aren't checked in alongside app code). A relative `json-output` override is resolved against the tool directory, so the location doesn't depend on the current working directory. Use `--from-intermediate` to regenerate code from it without calling the Figma API.

## Architecture

```
src/figma_tokens/
├── cli.py              # Thin orchestration
├── config.py           # Config loading + validation (incl. collection exclusions)
├── figma/
│   ├── client.py       # Figma REST API client
│   └── models.py       # Data models
├── pipeline/
│   ├── resolver.py     # Alias chain resolution
│   ├── enricher.py     # Value-matching enrichment
│   ├── intermediate.py # Intermediate JSON serialization
│   └── tree.py         # Token tree building
├── codegen/
│   ├── base.py         # Shared utilities (naming, formatting)
│   ├── kotlin.py       # Kotlin data class + factory generation
│   └── swift.py        # Swift struct + factory generation
└── graph/
    ├── collections.py  # Structural classification & dependency graph
    └── dependencies.py # Builder chain computation
```

## Config Reference

```toml
# Required
file-key = "YOUR_FIGMA_FILE_KEY"
language = "kotlin"  # or "swift"
output = "./output"

# Optional
token = "figd_..."           # Figma API token (prefer FIGMA_TOKEN env)
package = "com.example.tokens"
prefix = "DS"               # Prefix for class/struct names
shared-output = "./shared"
write-shared = true
json-output = "./json"       # Where to save figma-raw.json / tokens.json
                             # (defaults to tools/figma-tokens/json; relative paths
                             #  are resolved against the tool directory)
local-file = "./vars.json"  # Use saved JSON instead of API
save-json = "./vars.json"   # Save API response
collections-config = "./configs/collections.toml"  # Collection exclusion list
                             # (defaults to tools/figma-tokens/configs/collections.toml)
```

## Differences from v1

| Feature | v1 | v2 |
|---------|----|----|
| Collection classification | Heuristics + fallbacks | Structural inference |
| `--product` flag | Required for single-collection mode | Removed (always generates all) |
| Builder ordering | Has variable-before-definition bugs | Topological sort |
| Architecture | 750 LOC monolithic cli.py | Modular (graph, pipeline, codegen) |
| Dry-run | Not available | `--dry-run` flag |
| Hardcoded names | Some heuristics check "primitiv" in name | Zero (structural only) |
